### 핵심 개념

#### 자율로봇과 Embodied AI

- **자율로봇**: 사람이 하나하나 조종하지 않아도 스스로 느끼고(Sense), 판단하고(Plan), 움직이는(Act) 로봇. 원격 조종 → 반자율(목표만 줌) → 자율로 갈수록 로봇의 몫이 커진다.
- **Embodied AI**: 센서·모터라는 몸으로 물리 세계와 주고받으며 배우고 행동하는 AI. 챗봇과 달리 실시간으로 답해야 하고, 틀린 답이 곧 충돌·파손이라 시뮬레이터에서 먼저 시험한다.
- **HRI**: 사람 옆에서 일하는 로봇은 안전(속도·힘 제한, 사람 감지 시 감속·정지), 의도 전달(조명·화면·소리), 지시 이해(말·몸짓, 최근엔 언어 모델)가 필요하다.
- **로봇 통합**: 하드웨어·소프트웨어·환경을 한 시스템으로 맞추는 일. 흔한 문제는 센서 시간 동기화, 좌표계(TF) 불일치, 통신 지연이다. 상자(모듈) 사이 통신은 보통 ROS 2가 맡는다.

#### 자율화 기술 5단계

| 단계 | 하는 일 | 1일차에서 기억할 점 |
| --- | --- | --- |
| 센싱 | 카메라·라이다·IMU·휠 엔코더로 측정 | 센서 하나로는 부족해 서로 약점을 메운다(센서 융합). Nova Carter는 스테레오 카메라 여러 대·3D 라이다·IMU·엔코더를 가진다 |
| 인지 | 센서값의 의미 파악 | 검출(종류+상자), 분할(픽셀별), 깊이·3D 점구름, 6D 자세 추정. 대부분 딥러닝, 학습 데이터는 시뮬레이터로 만들 수 있다 |
| 위치추정·지도 | 나는 어디에 있나 | 바퀴 회전량만 쓰는 오도메트리는 오차가 쌓인다 → 지도와 맞춰 보정. 지도 없이 지도와 위치를 같이 만드는 것이 SLAM |
| 경로계획 | 목표까지 길 찾기 | 전역 계획(A*·Dijkstra) + 지역 계획(새 장애물 회피). 로봇팔은 관절 공간 궤적을 계획(MoveIt·cuMotion) |
| 제어 | 매 순간 모터에 "얼마나 세게" | 가장 많이 쓰는 건 PID. 학습 기반 제어(강화학습)는 DLI 3 |

#### 최근 흐름: 파운데이션 모델 · Physical AI · Cosmos

- **파운데이션 모델**: 많은 데이터로 크게 한 번 학습하고 여러 과제에 조금만 고쳐(파인튜닝) 쓰는 모델. 로봇에서는 보고(Vision)·이해하고(Language)·움직이는(Action) 모델로 넓어지는 중. 그래도 PID·A* 같은 고전 방법은 로봇 안쪽에서 계속 돈다.
- **왜 시뮬레이션인가**: 로봇이 배울 물리 세계 데이터는 인터넷 글처럼 많지 않고, 실물로 모으면 느리고 비싸고 위험하다 → 시뮬레이터에서 정답(라벨)이 붙은 데이터를 대량으로 만든다.
- **Cosmos (월드 파운데이션 모델)**: "이렇게 하면 다음에 어떻게 될까"를 영상으로 예측·생성. Transfer(시뮬 영상을 실사처럼 바꿔 데이터 다양화), Predict(실행 전 결과 상상), Reason(물리 상식으로 판단).
- **Mobility 모델**: 이동로봇의 "보고 → 갈 길 정하기"를 학습된 모델 하나로(X-Mobility, COMPASS). 이 과정에서는 개념만, 실습은 Nav2 + Isaac ROS.
- **LLM·VLM·RAG·VLA**: LLM은 말을 이해해 작업을 단계로 나누고, VLM은 영상까지 이해, RAG는 현장 정보(매뉴얼·지도)를 찾아 붙이고, VLA는 영상+말에서 관절 명령까지 바로 낸다(GR00T N 계열).

#### NVIDIA Isaac · ROS · Isaac ROS · NITROS

- **NVIDIA Isaac**: CUDA 가속 라이브러리·프레임워크·AI 모델 묶음. Three Computer Solution에서 이 과정 실습 PC(RTX)는 ②번(시뮬레이션) 자리이고, ①은 클라우드 API로 일부 체험(18·24일차), ③ Jetson은 PC 두 대로 흉내 낸다(7일차 HIL).
- **ROS**: 운영체제가 아니라 로봇 앱용 미들웨어. 생태계에 MoveIt(로봇팔), Nav2(이동로봇)가 있다. 이 과정은 ROS 2 Jazzy.
- **Isaac ROS**: ROS 2 위에 얹는 CUDA 가속 패키지와 AI 모델. 기존 ROS 2 앱에 그대로 넣을 수 있고, 참조 워크플로로 Isaac Manipulator(로봇팔)·Isaac Perceptor(이동로봇)가 있다. 이 과정은 Isaac ROS 4.0(Jazzy). 5.0은 Lyrical 전용이라 쓰지 않는다.
- **NITROS**: GPU 처리 데이터를 노드 사이에서 CPU로 복사하지 않고 넘긴다. ROS 2 Humble에서 들어온 Type adaptation(가속기 형식으로 주고받기)과 Type negotiation(노드들이 지원 형식을 알리고 최적 형식 선택)을 쓴다. RViz처럼 NITROS를 모르는 노드가 구독하면 일반 ROS 메시지로 자동 변환한다.

| 관련 기술 | 내용 |
| --- | --- |
| CUDA with NITROS | 내 노드에서 GPU 버퍼를 주고받기 |
| NITROS Bridge | 프로세스 사이 전달(CUDA IPC). 처음엔 ROS 1 사용자용 |
| PyNITROS | Python 노드의 PyTorch 버퍼를 복사 없이 C++ 노드로 |

**실습 ① 차동구동 기구학과 오도메트리** (`python3 diff_drive.py`)

```python
v = r * (wR + wL) / 2        # 정기구학: 바퀴 → 로봇
w = r * (wR - wL) / L
wR = (v + w * L / 2) / r     # 역기구학: 로봇 → 바퀴
wL = (v - w * L / 2) / r
# r = 0.14 m (바퀴 반지름), L = 0.413 m (바퀴 간격) — Nova Carter 크기 가정
```

- 원(v=0.5, ω=0.5)을 그리려면 오른쪽 바퀴가 더 빨라야 한다(4.31 > 2.83 rad/s). 제자리 회전은 두 바퀴가 같은 크기·반대 방향.
- 3% 무작위 미끄러짐 + 오른쪽 바퀴 1% 마모를 넣으면, 엔코더 추정 경로는 늘 같은 사각형인데 실제 경로는 72초(사각형 3바퀴) 뒤 약 1 m 어긋난다 → 위치추정이 필요한 이유.

**실습 ② PID로 90° 제자리 회전** (`python3 pid.py`)

```python
class PID:
    def __call__(self, error, dt=DT):
        deriv = 0.0 if self.prev is None else (error - self.prev) / dt
        self.prev = error
        u = self.kp * error + self.ki * (self.integral + error * dt) + self.kd * deriv
        if abs(u) < self.limit:   # 출력이 한계에 걸린 동안은 적분하지 않음 (anti-windup)
            self.integral += error * dt
        return float(np.clip(u, -self.limit, self.limit))
```

- 조건: 모터 시정수 0.25 s, 최대 2 rad/s.
- Kp=1: 넘치지 않지만 느림(2.9 s). Kp=6·20: 빨라지지만 오버슈트 약 10%.
- PD: 오버슈트 2.9%, 정착 1.3 s로 가장 빠름. D는 오차가 줄어드는 속도를 보고 미리 브레이크.
- 마찰 같은 상시 손실이 있으면 P만으로는 2.9° 오차가 남고, PI는 0.1°까지 줄인다.
- Go to Goal(전진 0.5 m/s, 방향만 P 제어): Kp 0.5는 목표 주변을 맴돌아 20초 안에 도착 못 함, 1.5·5.0은 6.3~6.4초에 도착.

**실습 ③ 창고 지도에서 경로계획** (`python3 astar.py`)

- 지도: `maps/carter_warehouse_navigation.png` (1픽셀 = 5 cm, 480×776). 장애물을 로봇 반지름 0.35 m만큼 부풀려 로봇을 점으로 보고 계획(Nav2 Costmap과 같은 원리).

### 내 메모 (RemNote)

[RemNote 11월 23일 데일리 문서](https://www.remnote.com/w/6ad729eabbafaa9b9157b9c2/November-23rd-2026-Lybm9osV1PxUAdNEl)에 적어 둔 메모를 옮기고, 틀린 부분은 고쳤다(아래 '고친 내용' 참고).

**리눅스 꿀팁**

- ctrl + shift + O or E : 터미네이터 창 분할
- Tab : 터미널 자동완성
- ctrl + shift + W : 터미널 닫기
- history : 명령어 입력 과거 리스트
- python -m : 모듈로서 실행해라.
- bin 폴더 : binary 폴더 (실행 파일이 들어 있는 곳. 예: `~/nvidia_dli/venv/bin/python`)
- python *.py : python 인터프리터를 이용한다는 의미
- 우분투는 기본적으로 파이썬으로 동작하는 파일들이 있어서 함부로 파이썬 버전을 바꾸면 시스템 동작에 영향을 줄 수 있다.
- /opt : optional, OS 기본 구성이 아닌 추가 소프트웨어를 설치하는 장소 (예: ROS 2는 `/opt/ros/jazzy`)
- curl : Client URL. URL로 데이터를 주고받는(내려받는) 명령
- export : 환경 변수 설정. 현재 터미널과 거기서 실행한 프로그램에만 적용되고, 터미널을 닫으면 사라진다 (계속 쓰려면 `~/.bashrc`에 추가)
- rosdep : ROS 패키지가 필요로 하는 의존성(시스템 패키지)을 찾아 설치해 주는 도구 (`rosdep install ...`)

**고친 내용**

| 원래 메모 | 고친 것 | 이유 |
| --- | --- | --- |
| Tap | Tab | 자동완성 키는 Tab |
| curl : command url | Client URL | curl은 Client URL의 줄임 |
| export : 시스템 변수 설정 | 환경 변수 설정 | 시스템 전체가 아니라 현재 셸과 자식 프로세스에만 적용 |
| rosdep : 의존성 패키지 | 의존성 설치 도구 | rosdep은 패키지가 아니라 의존성을 설치해 주는 도구 |
| /opt, bin 설명 | 예시 추가 | 틀린 건 아니지만 뜻을 분명히 |

#### 외부 자료로 보강한 정리

위 RemNote 메모를 공식 매뉴얼·문서와 대조해 보충했다(2026-11-26).

**Terminator 창 분할**

- `Ctrl+Shift+O` = Split Horizontally: 가로 경계선이 생겨 위·아래로 나뉜다. `Ctrl+Shift+E` = Split Vertically: 좌·우로 나뉜다. 블로그마다 반대로 적은 곳이 있는데, 공식 문서도 가로/세로 용어가 헷갈린다고 인정한다. 기준은 매뉴얼. ([terminator(1)](https://manpages.debian.org/trixie/terminator/x-terminal-emulator.1.en.html), [Getting Started](https://gnome-terminator.readthedocs.io/en/latest/gettingstarted.html))
- 같이 쓰는 키: `Ctrl+Shift+T` 새 탭, `Ctrl+Shift+W` 지금 터미널 닫기, `Ctrl+Shift+Q` 창 전체 닫기.

**python -m**

- 파일 경로가 아니라 모듈 이름을 주면, 파이썬이 모듈 검색 경로(sys.path)에서 찾아 스크립트로 실행한다. ([Python 명령줄 문서](https://docs.python.org/3/using/cmdline.html#cmdoption-m))
- 1일차 예: `python3 -m venv venv`는 표준 라이브러리의 venv 모듈을 실행한 것. `python -m pip install ...`처럼 쓰면 지금 켜진 그 파이썬에 딸린 pip가 돈다.

**bin 폴더와 venv**

- venv를 만들면 그 안에 `bin/`이 생기고 파이썬 실행 파일 사본(또는 링크)이 들어간다. `source venv/bin/activate`는 이 bin을 PATH 맨 앞에 붙일 뿐이라, 활성화 없이 `~/nvidia_dli/venv/bin/python`을 직접 불러도 같다. ([venv 문서](https://docs.python.org/3/library/venv.html))

**시스템 파이썬을 바꾸면 안 되는 이유**

- Ubuntu의 업데이트 도구 같은 시스템 프로그램이 기본 python3에 묶여 있어서, 다른 버전을 python3로 바꿨다가 OS를 다시 설치해야 했던 사례가 흔하다. ([Newcastle Univ. IT 안내](https://blogs.ncl.ac.uk/helengriffiths/?p=228))
- 그래서 Ubuntu 24.04는 PEP 668에 따라 시스템 파이썬에 바로 `pip install`하면 `externally-managed-environment` 오류로 막는다. 해결책이 바로 오늘 만든 venv. ([PEP 668](https://peps.python.org/pep-0668/), [Ubuntu 24.04 pip 오류](https://ubuntuhandbook.org/index.php/2024/03/pip-install-error-ubuntu-2404))

**/opt**

- FHS(리눅스 디렉터리 표준)에서 /opt는 "추가 응용 소프트웨어 패키지" 자리이고, 패키지마다 `/opt/<패키지>` 하위 폴더를 쓴다. ROS 2가 `/opt/ros/jazzy`에 깔리는 이유. ([FHS 3.0 /opt](https://specifications.freedesktop.org/fhs/latest/opt.html), [Ubuntu FHS 설명](https://ubuntu.com/project/docs/how-ubuntu-is-made/concepts/filesystem-hierarchy-standard/))

**curl**

- 매뉴얼 제목이 "transfer a URL". HTTP·HTTPS·FTP 등 여러 프로토콜로 서버와 데이터를 주고받고, 사람 입력 없이 돌도록 설계돼 설치 스크립트에서 자주 쓴다. 받은 내용을 해석하지는 않는다. ([curl(1)](https://manpages.debian.org/wheezy/curl/curl.1.en.html))

**export**

- export는 변수를 "자식 프로세스에게 넘길 것"으로 표시한다. 자식은 부모 환경의 복사본을 받으므로, 자식에서 바꾼 값은 부모로 돌아오지 않는다. ([Bash 매뉴얼 Environment](https://www.gnu.org/software/bash/manual/html_node/Environment.html), [Baeldung](https://www.baeldung.com/linux/bash-variables-export))
- 그래서 `ROS_DOMAIN_ID`를 export한 터미널에서 띄운 ros2·Isaac Sim만 그 값을 본다. 새 터미널마다 쓰려면 `~/.bashrc`에 넣는다.

**rosdep**

- 패키지의 package.xml에 적힌 의존성을 읽어 OS 패키지 관리자(apt)로 설치해 주는 명령줄 도구. ROS 2에서는 ros-dev-tools에 포함. ([rosdep 튜토리얼](https://docs.ros.org/en/lyrical/Tutorials/Intermediate/Rosdep.html), [rosdep 개요](https://docs.ros.org/en/independent/api/rosdep/html/overview.html))
- 순서: `sudo rosdep init`(처음 한 번, /etc/ros/rosdep 초기화) → `rosdep update`(인덱스 갱신, 가끔) → `rosdep install --from-paths src -y --ignore-src`. 뭘 설치할지 미리 보려면 `-s`(시뮬레이션). ([rosdep 명령 참조](https://docs.ros.org/independent/api/rosdep/html/commands.html))

### 복습 질문

> [!question]- Q1. 바퀴 엔코더만으로 위치를 계산하면 왜 시간이 갈수록 틀리나? 어떻게 고치나?
> 엔코더는 명령대로·설계 치수대로 돌았다고 믿지만, 실제로는 미끄러짐과 바퀴 마모가 있어 오차가 쌓인다(실습 ①에서 72초 뒤 약 1 m). 라이다·카메라로 본 주변을 지도와 맞춰 위치를 고친다(AMCL 같은 위치추정, 지도가 없으면 SLAM).

> [!question]- Q2. PID의 P·I·D는 각각 무슨 역할인가?
> P는 오차에 비례해 빠르게 반응(크면 오버슈트), I는 마찰처럼 계속 남는 오차를 쌓아서 없앰, D는 오차가 줄어드는 속도를 보고 미리 브레이크를 걸어 넘침을 줄인다.

> [!question]- Q3. A*가 Dijkstra보다 적은 칸을 보고도 같은 최단 경로를 찾는 이유는?
> 출발점부터의 거리에 "목표까지 남은 직선거리"를 더해 목표 쪽부터 펼치기 때문. 실습에서는 같은 29.2 m 경로를 Dijkstra 20만 칸, A* 7만 칸으로 찾았다.

> [!question]- Q4. 챗봇이 틀리는 것과 로봇이 틀리는 것은 무엇이 다른가?
> 로봇은 실시간으로 답해야 하고, 틀린 답이 곧 충돌·파손으로 이어진다. 그래서 시뮬레이터에서 먼저 시험한다.

> [!question]- Q5. NITROS가 없애는 것은 무엇이고, RViz처럼 NITROS를 모르는 노드가 구독하면 어떻게 되나?
> GPU로 처리한 데이터를 다음 노드에 넘길 때 생기는 CPU↔GPU 메모리 복사를 없앤다(Type adaptation + Type negotiation). NITROS를 모르는 노드가 구독하면 자동으로 일반 ROS 메시지로 바꿔 준다.

> [!question]- Q6. "빨간 상자를 선반에 올려 줘"를 처리할 때 LLM과 PID는 각각 무엇을 맡나?
> LLM은 말을 이해해 작업을 단계(상자 찾기 → 잡기 → 선반으로 이동 → 놓기)로 나누고, PID는 그 단계를 실행할 때 관절·바퀴 모터를 목표값으로 매 순간 제어한다.

> [!question]- Q7. `source /opt/ros/jazzy/setup.bash`를 `.bashrc`에 넣지 않는 이유는?
> Isaac Sim은 내장 ROS 2 라이브러리를 쓰는데, 시스템 ROS 2 환경이 섞이면 안 되는 경우(4일차 4-3)가 있어서다. ROS 2가 필요한 터미널에서만 직접 source한다.
