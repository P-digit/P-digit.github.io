> 2일차 · Getting Started: Simulating Your First Robot in Isaac Sim (S-OV-27)

Isaac Sim 5.1을 켜고 화면 구성과 뷰포트 조작을 익힌 뒤, 큐브 떨어뜨리기로 물리가 동작하는 데 필요한 것(Physics Scene, Rigid Body + Collider, Ground Plane)을 하나씩 확인했다. 이어서 큐브 몸체와 원기둥 바퀴 4개를 SimpleRobot Xform으로 묶고, Revolute Joint로 연결한 다음 뒷바퀴에 Angular Drive를 달아 로봇을 직진·회전시켰다. 실제 이동 거리를 계산값과 비교해 1일차 기구학과 연결했다.

### 학습 목표

공식 과정 S-OV-27 (1.5H, 공개 본문: [docs.nvidia.com/learning/physical-ai](http://docs.nvidia.com/learning/physical-ai) → Getting Started With Isaac Sim → Building Your First Robot in Isaac Sim)

- Isaac Sim 화면을 익힌다
- 기본 도형으로 로봇(몸체·바퀴·관절)을 만든다
- 물리를 설정한다
- OmniGraph로 조종한다
- RGB 카메라와 2D 라이다를 단다
- 센서 데이터를 ROS 2로 보내 RViz에서 본다

오늘 강의자료는 앞의 세 가지(화면, 로봇 만들기, 물리)를 다룬다. 같은 강의를 미리 혼자 공부한 기록: [2026-11-25 Isaac Sim 첫 로봇 만들기 학습지](https://app.notion.com/p/42347b7cc0d481858973d9275f7ecc99)

### 핵심 개념

#### Isaac Sim 화면과 OpenUSD 용어

| 영역 | 하는 일 |
| --- | --- |
| 위 메뉴 | File · Edit · Create(도형·물리·센서 추가) · Window · Tools |
| 가운데 Viewport | 3D 장면. 왼쪽 아래 축: 빨강 X · 초록 Y · 파랑 Z(위) |
| 왼쪽 도구 막대 | 선택·이동·회전·크기, 그 아래 ▶ Play / ■ Stop |
| 오른쪽 위 Stage | 장면의 모든 물체(Prim) 계층. 새 장면에는 World와 Environment(defaultLight) |
| 오른쪽 아래 Property | 선택한 Prim의 값(Transform·물리·재질) |
| 아래 Content | 에셋 브라우저(제공 로봇·환경) |

- Isaac Sim의 장면은 OpenUSD 파일이다. **Stage** = 장면 전체, **Prim** = 장면 안의 물체 하나, **Xform** = 위치·회전·크기만 가진 빈 Prim(묶음용). OpenUSD는 17일차에 자세히.
- 단위는 미터(m), 위쪽은 Z.
- 값은 항상 ■ Stop 상태에서 바꾼다. Stop을 누르면 Play 전 상태로 돌아간다.

| 뷰포트 동작 | 방법 |
| --- | --- |
| 앞뒤·좌우 / 위아래 이동 | 오른쪽 버튼 누른 채 W·A·S·D / Q·E |
| 둘러보기 | 오른쪽 버튼 누른 채 끌기 |
| 확대·축소 | 마우스 휠 (또는 Alt + 오른쪽 버튼 끌기) |
| 평행 이동 | 가운데 버튼 누른 채 끌기 |
| 선택한 물체로 | F |

#### 물리가 동작하려면 필요한 것

큐브 하나를 두고 단계별로 확인했다.

| 상태 | Play 결과 | 이유 |
| --- | --- | --- |
| Cube만 있음 | 아무 일도 없음 | 보이는 모양(visual mesh)일 뿐 |
|   • Physics Scene | 그대로 | 중력(기본 지구 중력, −Z)은 생겼지만 큐브가 아직 물리 물체가 아님 |
|   • Rigid Body with Colliders Preset | 끝없이 떨어짐 | 바닥이 없음. 1초에 z = −5.3 m (½ · 9.81 · 1² ≈ 4.9 m + α) |
|   • Ground Plane, Cube z = 1 | 바닥 위에 멈춤 | 충돌면(CollisionPlane)은 보이는 판(25 m)보다 무한히 넓다 |

- **Rigid Body** = 질량이 있어 힘과 중력을 받는 물체. **Collider** = 충돌 모양. 눈 아이콘 > Show By Type > Physics > Colliders > Selected로 충돌 모양을 초록 선으로 볼 수 있다.
- Colliders Preset만 주면 떨어지지 않지만 다른 물체가 부딪히는 "고정된 벽"이 된다.

#### 계층(부모-자식)과 회전 관절

- 부모를 옮기면 자식이 함께 움직인다. 로봇 전체를 SimpleRobot Xform 하나로 묶고, 자식(Cube)의 Translate는 (0, 0, 0) 그대로 둔다.
- 몸체와 바퀴를 Rigid Body로만 두면 Play 때 따로 떨어진다 → **Revolute Joint**로 연결해야 한다.
- 관절은 선택 순서가 중요하다: 먼저 고른 것이 Body 0(Cube), Ctrl로 추가한 것이 Body 1(바퀴).
- 만든 직후 기본값(Axis X, Local Rotation 0 = (90, 0, 0))은 틀린 값이다. 바퀴 축은 로봇의 왼쪽 방향(Y)이므로 Axis Y, Local Rotation 0 (0, 0, 0), Local Rotation 1 (−90, 0, 0)으로 고친다.
- Local Position 0 = (0.25, 0.75, 0)처럼 몸체 기준 좌표로 표시된다. 몸체가 X로 2배 늘어나 있어 실제로는 0.5 m 앞이다.

#### 구동: Angular Drive

- 뒷바퀴 관절에 Angular Drive를 달고 Damping을 크게(10000) 주면 "목표 속도를 강하게 따라가는" 속도 제어가 된다(1일차 PID의 D와 같은 생각).
- Target Velocity의 단위는 °/s다. 50 °/s = 0.873 rad/s.
- 양쪽 +50이면 직진, 왼쪽 +50 · 오른쪽 −50이면 오른쪽(시계 방향)으로 돈다.
- 앞바퀴는 구동이 없어 옆으로 미끄러져야 돌 수 있으므로(4륜 스키드 조향) 생각보다 적게 돈다.

### 실습 / 코드

#### 1. Isaac Sim 실행

```bash
mkdir -p ~/nvidia_dli/work/day02        # 오늘 만든 장면을 저장할 폴더
source /opt/ros/jazzy/setup.bash        # 4교시 이후 ROS 2를 쓰므로 미리
~/nvidia_dli/isaacsim/isaac-sim.sh
```

- File > New → "Would you like to save this stage?"는 Don't Save.
- 저장: File > Save As → 경로 칸에 `~/nvidia_dli/work/day02/` 입력 후 Enter, 파일명 `simple_robot.usd`. 이후 단계마다 Ctrl+S.

#### 2. 큐브 떨어뜨리기 (물리 기초)

1. Create > Mesh > Cube (1 m 정육면체, 중심 기준 ±0.5 m)
1. Create > Physics > Physics Scene
1. Cube 선택 후 우클릭 > Add > Physics > Rigid Body with Colliders Preset
1. Create > Physics > Ground Plane, Cube Translate Z = 1 → Play 2초, 바닥 위에 멈춤

#### 3. 4륜 로봇 조립

1. **몸체**: Cube Translate (0, 0, 0), Scale (2, 1, 0.5) → 길이 2 m · 폭 1 m · 높이 0.5 m. World 우클릭 > Create > Xform → 이름 SimpleRobot, Cube를 끌어다 자식으로.
1. **바퀴**: SimpleRobot 우클릭 > Create > Mesh > Cylinder → Orient X = 90(눕히기), Scale (0.75, 0.75, 0.25)(지름 0.75 m · 폭 0.25 m), Translate (0.5, 0.75, 0), 이름 Front_Left_Wheel. Duplicate로 Front_Right (0.5, −0.75, 0), Rear_Left (−0.5, 0.75, 0), Rear_Right (−0.5, −0.75, 0).
1. 바퀴 4개를 Ctrl로 모두 선택 → 선택된 바퀴 위에서 바로 우클릭 > Add > Physics > Rigid Body with Colliders Preset.
1. **관절**: Cube 클릭 → Ctrl + 바퀴 클릭 → 바퀴 위 우클릭 > Create > Physics > Joint > Revolute Joint. 이름 Front_Left_Joint, Axis Y, Local Rotation 0 (0, 0, 0), Local Rotation 1 (−90, 0, 0). 나머지 세 바퀴도 같게.
1. SimpleRobot Translate Z = 0.4 (바퀴 반지름 0.375 m보다 조금 위).
1. **구동**: Rear_Left_Joint·Rear_Right_Joint 우클릭 > Add > Physics > Angular Drive → Damping 10000, Target Velocity 50.
1. 끝나면 ■ Stop, Target Velocity를 0으로 되돌리고 Ctrl+S (다음 단계에서 제어기가 이 값을 대신 줌).

최종 값 대조표:

| 항목 | 값 |
| --- | --- |
| Cube | Translate (0, 0, 0), Scale (2, 1, 0.5) |
| 바퀴 | Orient (90, 0, 0), Scale (0.75, 0.75, 0.25), Translate (±0.5, ±0.75, 0) |
| 관절 | Axis Y, Local Rotation 0 (0, 0, 0), Local Rotation 1 (−90, 0, 0) |
| 뒷바퀴 구동 | Angular Drive, Damping 10000, Target Velocity 50 |
| SimpleRobot | Translate (0, 0, 0.4) |

#### 4. 측정 결과

| 실험 | 결과 (강사 PC) | 계산 / 해석 |
| --- | --- | --- |
| 양쪽 +50 °/s, 4초 | x = 0 → 1.265 m | 0.873 rad/s × 0.375 m = 0.327 m/s × 4 s = 1.31 m. 미끄러짐만큼 덜 감 |
| 왼쪽 +50 · 오른쪽 −50, 4초 | 오른쪽으로 18.8° 회전 | 구동 없는 앞바퀴가 옆으로 미끄러져야 해서 적게 돈다(스키드 조향) |

### 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 로봇이 끌리듯 움직임 | 바퀴가 몸체보다 높거나, 관절의 Body 0/1 순서가 바뀜 | Body 0 = Cube, Body 1 = 바퀴인지 확인. Property의 Body 0/1 옆 폴더 아이콘으로 다시 고름 |
| 바퀴가 엉뚱하게 돎 | Axis나 Local Rotation 0/1 값이 틀림 | 대조표와 비교. 관절을 하나씩 꺼 보며(Joint Enabled 해제) 범위를 좁힘 |
| 바퀴 4개에 물리가 하나에만 들어감 | 우클릭 전에 다른 곳을 클릭해 선택이 하나로 줄음 | Ctrl로 4개를 고른 뒤 선택된 바퀴 위에서 바로 우클릭 |
| Save As에서 폴더 없음 오류 | 저장 폴더를 안 만듦 | `mkdir -p ~/nvidia_dli/work/day02` |

### 환경 메모

- 공식 본문은 Isaac Sim 4.5 · ROS 2 Humble 기준이고, 강의는 5.1 · Jazzy에서 직접 확인한 절차다. 5.1에서 다른 곳은 세 군데: 카메라 회전, 차동 제어기 관절 칸, 센서 마운트 강체.
- 공식 본문은 `isaac-sim.selector.sh`로 시작하고 ROS Bridge를 끄라고 하지만, 5.1에서는 ROS 2를 먼저 source하고 `isaac-sim.sh`로 바로 실행해도 된다.
- 5.1의 Property 패널은 회전을 **Orient**로 표시한다(공식 본문의 Rotate와 같은 칸). Transform 대신 Add Transforms 버튼이 보이면 먼저 눌러 칸을 만든다.

### 내 메모 (RemNote)

[RemNote 11월 24일 데일리 문서](https://www.remnote.com/w/6ad729eabbafaa9b9157b9c2/November-24th-2026-kyxyJ4bFDjjKD7HLU)에 적어 둔 메모를 옮기고, 틀린 부분은 고쳤다(아래 '고친 내용' 참고).

**자율로봇 · 센서**

- AGV : Automated Guided Vehicle. 바닥의 선·마커 같은 정해진 경로를 따라감 (ex 검은 선). 스스로 길을 찾는 AMR과 구분
- 휴머노이드 중요성 : 우리가 사는 세계의 모든 문명은 사람 인체공학에 맞게 설계가 되어 있기 때문에
- RGBD : RGB 영상 + Depth(픽셀별 거리)
- disparity : 스테레오 카메라의 왼쪽·오른쪽 영상에서 같은 점이 가로로 어긋난 정도(픽셀). 가까운 물체일수록 크고, 깊이 = 초점거리 × 두 카메라 간격 ÷ disparity
- 차동구동 : 좌우 바퀴의 속도 차로 방향을 바꿈. 두 바퀴가 반대 방향(앞·뒤)으로 돌면 제자리 회전
- 여러 시뮬레이션 환경에서 검증한다
- 검증 , 신뢰 : safety gate 안전 신뢰도를 보장해야 한다.
- 점구름 : Point cloud. 3D 위치를 가진 점들의 집합 (라이다·스테레오 카메라로 얻음)

**Isaac Sim**

- physicsScene : 장면에 물리 시뮬레이션을 켜는 전역 설정 (중력 방향·크기, 시간 간격 등)
- Rigid Body with Colliders Preset : 강체 설정 및 충돌면 설정
- 라이다 장착시에 마운트 항상 장착
- Xform : 추상적 prim . 좌표계(그룹)
- pose (6-D) : x, y, z, r, p, y (roll, pitch, yaw)
- roll : 보통 동체의 진행방향 x축의 회전
- pitch : 날개방향 y축의 회전
- yaw : z축(위쪽, x × y 외적 방향)의 회전
- orient 기준으로 scale이 바뀌는 것이 아닌, 원본 형태에서 scale 바뀜 (예: 원기둥을 Orient X 90으로 눕혀도 Scale (0.75, 0.75, 0.25)의 0.25는 원래 높이 축에 적용돼 바퀴 폭이 됨)

**고친 내용**

| 원래 메모 | 고친 것 | 이유 |
| --- | --- | --- |
| physicsScene : 물성 적용 | 물리 시뮬레이션 전역 설정 | 물성(마찰·반발)은 Physics Material이 정함. Physics Scene은 중력 등 장면 전체 설정 |
| disparity : (비어 있음) | 뜻 채움 | 설명이 없었음 |
| 점구름 : vertex의 집합 | 점들의 집합 | vertex는 메시(면)의 꼭짓점 용어. 점구름은 연결 없는 점들 |
| AGV, RGBD, 차동구동, yaw | 풀어서 보충 | 틀린 건 아니지만 뜻을 분명히 |

#### 외부 자료로 보강한 정리

위 RemNote 메모를 공식 문서·논문과 대조해 보충했다(2026-11-26).

**AGV vs AMR**

- AGV는 바닥의 자기 테이프·매립 유도선·마커를 따라 정해진 경로만 다니고, 장애물이 길을 막으면 치워질 때까지 멈춰 기다린다. AMR은 센서와 지도로 스스로 경로를 짜고 장애물을 돌아간다. 1일차의 Nav2 창고 데모가 AMR 방식. ([Analog Devices](https://ez.analog.com/ez-blogs/b/engineerzone-spotlight/posts/finding-the-right-fit-for-your-industrial-automation-need---agvs-or-amrs), [Zebra](https://prod-www.zebra.com/gb/en/blog/posts/2022/what-is-the-difference-between-an-agv-and-amr.html))

**휴머노이드가 중요한 이유**

- 메모의 "세상이 사람 몸에 맞게 설계됐다"와 같은 논리를 업계도 쓴다: 사람을 위해 지어진 환경에서 하나의 기계가 여러 기술을 배워 일하는 것이 핵심이라는 설명(NVIDIA 발표 속 Agile Robots CEO 발언). ([NVIDIA 뉴스룸](https://nvidianews.nvidia.com/news/nvidia-advances-isaac-platform-for-general-purpose-robotics-with-new-reference-humanoid-frameworks-simulation-pipelines-and-data))

**RGB-D · disparity · 점구름**

- RGB-D = RGB 영상 + 깊이 맵. 깊이 맵은 흑백 영상처럼 생겼지만 각 픽셀 값이 센서~표면 거리이고, RGB 픽셀과 1:1로 대응한다. ([3D 검출 서베이](https://arxiv.org/pdf/2201.09354))
- 깊이 Z = f × B ÷ d (f: 초점거리, 픽셀 단위 / B: 두 카메라 간격 / d: disparity). 깊이 오차는 Z²에 비례해 커지므로 멀수록 급격히 부정확하고, 간격 B가 넓을수록 먼 곳을 정밀하게 잰다. ([Intel RealSense 논문](https://arxiv.org/pdf/1705.05548), [MIT 계산사진학 교재](https://people.csail.mit.edu/fredo/comp-photo-book/02-fundamentals-07-multiple-view-geometry.html))
- 점구름: 점마다 x·y·z 좌표와 선택적으로 강도·색을 가진 3D 점들의 집합. 점 사이에 면이나 연결이 없다는 점이 메시(vertex + 면)와 다르다. ([Voxel51 용어집](https://voxel51.com/glossary/point-cloud))

**검증 · safety gate**

- 정해진 표준 용어는 아니고, "시뮬레이션 결과를 실물에 올리기 전에 반드시 통과해야 하는 검증 관문"이라는 뜻으로 정리해 둔다. 이 과정에서는 SIL(5일차) → HIL(7일차) 순서로 다룬다.

**Physics Scene**

- 중력 방향·크기, 시뮬레이션 시간 간격, 솔버 설정을 담는 장면 전체 설정. ([Omniverse Physics 문서](https://docs.omniverse.nvidia.com/extensions/latest/ext_physics/simulation-control/physics-settings.html))
- 물리는 고정된 시간 간격으로 돈다. 기본값은 초당 60 스텝이고 화면 프레임과 따로다(예: 120 스텝 + 60 fps면 한 프레임에 물리 2 스텝). ([Isaac Sim Physics 기초](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/physics/simulation_fundamentals.html))

**Xform**

- OpenUSD의 Xform은 이동·회전·크기 변환을 저장하는 prim이고, 그 변환이 자식 prim에 적용된다. 여러 도형을 하나로 묶는 중간 노드로 쓰라고 권장된다(SimpleRobot이 바로 이 용도). ([Learn OpenUSD: Xform](https://docs.nvidia.com/learn-openusd/latest/scene-description-blueprints/xform.html), [SimReady 규칙](https://nvidia.github.io/simready-foundation/latest/capabilities/hierarchy/requirements/root-is-xformable.html))

**pose와 roll · pitch · yaw**

- ROS 표준(REP 103): 몸체 기준 x 앞 · y 왼쪽 · z 위, 오른손 좌표계, 단위는 SI(각도는 라디안). 고정축 기준 roll·pitch·yaw = X·Y·Z축 회전. ([REP 103](https://reps.openrobotics.org/rep-0103/))
- 오른손 법칙이라 +yaw는 위에서 볼 때 반시계(왼쪽) 회전. 3일차에 "각속도 +는 왼쪽으로 돌기"였던 이유.

**Orient와 Scale 순서**

- USD는 변환을 `xformOpOrder` 목록 순서로 쌓는데, 목록의 뒤쪽일수록 "가장 안쪽(로컬)" 연산이다. 보통 순서가 [translate, orient, scale]이라 점에는 scale → 회전 → 이동 순으로 적용된다. ([OpenUSD UsdGeomXformable](https://openusd.org/dev/api/class_usd_geom_xformable.html), [openusd-rs 설명](https://docs.rs/crate/openusd/0.4.0/source/src/schemas/geom/xform.rs))
- 그래서 원기둥을 Orient X 90으로 눕혀도 Scale (0.75, 0.75, 0.25)의 0.25는 눕히기 전 원래 높이 축(Z)에 먼저 적용돼 바퀴 폭이 된다. 메모가 맞다.

### 복습 질문

> [!question]- Q1. Cube에 Physics Scene만 추가하고 Play하면 왜 떨어지지 않나?
> 장면에 중력은 생겼지만 Cube가 아직 물리 물체(Rigid Body)가 아니기 때문이다. Rigid Body with Colliders Preset을 줘야 중력을 받는다.

> [!question]- Q2. Rigid Body with Colliders Preset과 Colliders Preset만 준 것의 차이는?
> 전자는 질량이 있어 중력으로 떨어지고 부딪힌다. 후자는 떨어지지 않고 다른 물체가 부딪힐 수만 있는 고정된 벽이 된다.

> [!question]- Q3. Revolute Joint를 만들 때 Cube를 먼저 고르고 바퀴를 나중에 고르는 이유는?
> 선택 순서가 Body 0(몸체) → Body 1(바퀴)을 정한다. 순서가 바뀌면 로봇이 끌리듯 움직이는 등 이상하게 동작한다.

> [!question]- Q4. 바퀴 관절의 Axis를 Y로 바꾸는 이유는?
> 로봇은 X 방향으로 전진하고 바퀴 축은 로봇의 왼쪽 방향(Y)이기 때문이다. 기본값 X는 틀린 값이다.

> [!question]- Q5. Target Velocity 50으로 4초 동안 이론상 몇 m 가고, 실제는 왜 덜 가나?
> 50 °/s = 0.873 rad/s, × 반지름 0.375 m = 0.327 m/s, × 4 s = 1.31 m. 실제 측정은 1.265 m로 미끄러짐만큼 덜 간다.

> [!question]- Q6. 왼쪽 +50 · 오른쪽 −50으로 돌렸는데 18.8°밖에 안 도는 이유는?
> 앞바퀴는 구동이 없어서 로봇이 돌려면 옆으로 미끄러져야 한다(4륜 스키드 조향). 그 마찰 때문에 회전이 작다.
