> 3일차 · Getting Started: Simulating Your First Robot in Isaac Sim (S-OV-27)

2일차에 만든 4륜 로봇에 Articulation Root를 달고 Differential Controller 그래프로 (v, ω) → 좌우 바퀴 속도를 만들어 키보드(WASD)로 조종했다. Fixed Joint로 몸체에 고정한 센서 자리에 RGB 카메라와 PhysX 2D 라이다를 달고, OmniGraph의 ROS 2 노드로 `/scan_lidar`·`/rgb` 토픽을 내보내 RViz2에서 확인했다. 이로써 S-OV-27(Simulating Your First Robot)을 끝냈다.

### 학습 목표

S-OV-27의 남은 목표(2일차에서 이어짐). 앞부분: [2일차 · Isaac Sim 화면·물리 기초와 4륜 로봇 만들기](https://app.notion.com/p/42447b7cc0d4815c8ea3fad3202292d4)

- OmniGraph로 조종한다
- RGB 카메라와 2D 라이다를 단다
- 센서 데이터를 ROS 2로 보내 RViz에서 본다

### 핵심 개념

#### Articulation Root

- 관절로 이어진 강체들을 "하나의 로봇"으로 묶어 물리 엔진이 한꺼번에 푼다. 관절이 덜 흔들리고, 제어기가 관절을 이름으로 찾을 수 있다.
- 제어기를 만들기 전에 먼저 붙인다: SimpleRobot 우클릭 > Add > Physics > Articulation Root.

#### Differential Controller 그래프

| 노드 | 하는 일 |
| --- | --- |
| On Playback Tick | 매 프레임 실행 신호 |
| Differential Controller | (v, ω) → 왼·오 바퀴 각속도 (1일차 역기구학) |
| Articulation Controller | 그 속도를 관절에 줌 |
| Make Array (ArrayNames) | 어느 관절인지 |
| W·A·S·D (Read Keyboard State) | 키가 눌렸는지 (True/False) |
| ToDouble · NegOne · Multiply · Add | W − S → 앞뒤, A − D → 좌우 |
| ScaleLinear (5) · ScaleAngular (6) | 키 하나가 주는 속도 5 m/s · 6 rad/s. 이 로봇에게 5 m/s는 빠름 |

- Desired Linear/Angular Velocity를 직접 넣으면 그 속도로 움직인다. 각속도 +는 왼쪽으로 돌기.
- 바퀴가 덜콹거리는 느낌은 바퀴와 바닥이 같은 기본 물리 재질이라 미끄러지기 때문(NVIDIA 공식 튜토리얼도 같은 설명).

#### 센서 달기

- 센서는 Fixed Joint(움직임이 없는 관절)로 몸체에 고정한 Xform(Front_Sensor, Rigid Body) 아래에 둔다. 선택 순서는 바퀴 관절과 같이 Cube(Body 0) → Front_Sensor(Body 1).
- **PhysX 라이다는 물리 충돌 모양만 본다.** 보이는 모양만 있는 장애물은 선이 그냥 통과하고, Colliders를 주면 장애물에서 멈춘다.
- 라이다가 너무 낮으면 바퀴를 맞힌다(로봇 바로 옆에 동그렇게 점이 찍힘).

#### ROS 2 로 데이터 보내기

- Isaac Sim은 ROS 2 Bridge 익스텐션(`isaacsim.ros2.bridge`, 5.1은 기본 ENABLED)으로 ROS 2 노드 역할을 한다. OmniGraph에 ROS 2 노드를 넣으면 토픽이 나간다.
- 토픽에는 시뮬레이션 시간(Isaac Read Simulation Time)을 Time Stamp로 넣는다.
- RViz2의 Fixed Frame은 메시지의 frame_id(`sim_lidar`)와 같아야 점이 보인다(공식 퀴즈 문제). Fixed Frame이 로봇에 붙어 있으므로 RViz에서는 로봇이 가만히 있고 주변이 움직이는 것처럼 보인다. 지도 기준 좌표는 TF와 함께 5일차.
- 강의장에서는 `ROS_DOMAIN_ID`를 좌석별로 나눠 다른 PC 토픽과 섞이지 않게 한다. Isaac Sim 터미널과 RViz 터미널의 값이 같아야 한다.

### 실습 / 코드

#### 1. Differential Controller로 조종

Tools > Robotics > OmniGraph Controllers > Differential Controller 창에 넣는 값:

| 칸 | 값 |
| --- | --- |
| graph path | /Graphs/differential_controller (기본값) |
| Robot Prim | /World/SimpleRobot |
| wheel radius | 0.375 (지름 0.75의 절반) |
| distance between wheels | 1.5 (좌우 바퀴 y = ±0.75) |
| Right Joint Name | **Rear_Left_Joint** (5.1 주의: 서로 바꿔 넣음) |
| Left Joint Name | **Rear_Right_Joint** |
| Use Keyboard Control (WASD) | 처음엔 끔, 키보드 단계에서 켬 |

1. OK → Stage의 Graphs > differential_controller 우클릭 > Open Graph로 노드 확인.
1. DifferentialController 노드 선택 → Desired Linear Velocity 1 → Play 3초.
1. Desired Angular Velocity 1 → Play 3초(왼쪽으로 도는지 확인).
1. 키보드: 그래프 삭제 → 같은 값 + Use Keyboard Control 체크로 다시 생성 → ScaleLinear Value를 1.5로 → Play 후 뷰포트를 한 번 클릭하고 WASD.

| 실험 (강사 PC) | 결과 | 해석 |
| --- | --- | --- |
| v = 1 m/s, 3초 | 2.78 m 전진 | 계산 3 m |
| ω = +1 rad/s, 3초 | 왼쪽 13.2° | 4륜 스키드라 적게 돈다 |
| 관절 칸을 이름대로 넣고 ω = +1, 3초 | −10.7° (오른쪽) | 좌우가 뒤바뀜, 틀림 |
| 키보드 W 2초 (ScaleLinear 1.5) | 2.63 m 전진 | 1.5 × 2 = 3 m, 출발 가속만큼 덜 감 |
| 키보드 A 1.5초 | 왼쪽 32.8° | 관절 칸을 바꿔 넣어 방향이 맞음 |

#### 2. 센서 달기

1. SimpleRobot 우클릭 > Create > Xform → 이름 Front_Sensor, Translate (0.9, 0, 0.3)(몸체 위 앞쪽 끝) → Add > Physics > Rigid Body.
1. Cube 클릭 → Ctrl + Front_Sensor → Create > Physics > Joint > Fixed Joint (Body 0 = Cube, Body 1 = Front_Sensor 확인).
1. Front_Sensor 우클릭 > Create > Mesh > Cube → 이름 Sensor_Mount, Scale (0.1, 0.1, 0.1), **Colliders Preset만**.
1. Sensor_Mount 우클릭 > Create > Camera → 이름 Robot_Camera, Translate (0.5, 0, 0)(실제 5 cm, 큐브 앞면), Orient **(90, −90, 0)**.
1. World 바로 아래에 장애물 4개(Cube·Cone·Cylinder·Cube)를 로봇 앞(+X) 1~5 m에 놓기.
1. Perspective > Cameras > Robot_Camera로 로봇 시점 확인. Window > Viewports > Viewport 2로 두 화면 보기.
1. Front_Sensor 선택 → Create > Sensors > PhysX Lidar > Rotating → Lidar Translate Z = 0.1.
1. Lidar의 Raw USD Properties에서 `draw` 검색 → drawLines(·drawPoints) 체크 → Play: 선이 장애물을 통과.
1. 장애물 4개에 Rigid Body with Colliders Preset(또는 Colliders Preset만) → Play: 빨간 선이 장애물에서 멈춤.

#### 3. ROS 2로 데이터 보내기

```bash
# 터미널 1: ROS 2를 source한 뒤 Isaac Sim 실행
source /opt/ros/jazzy/setup.bash
ros2 topic list                 # /parameter_events · /rosout 이 나오면 준비 완료
~/nvidia_dli/isaacsim/isaac-sim.sh
# File > Open Recent 로 simple_robot.usd 열기
echo $ROS_DOMAIN_ID             # 내 좌석번호 확인 (모든 터미널 동일)
```

**라이다 → LaserScan (Action Graph** `ROS2_LidarStream`**)**: World 우클릭 > Create > Visual Scripting > Action Graph

| 노드 | 연결 / 설정 |
| --- | --- |
| On Playback Tick | Tick → Read Lidar Beams의 Exec In |
| Isaac Read Lidar Beams | Exec Out → Publish Laser Scan의 Exec In. Lidar Prim = World/SimpleRobot/Front_Sensor/Lidar. 출력(Azimuth Range·Depth Range·Horizontal Fov·Horizontal Resolution·Intensities Data·Linear Depth Data·Num Cols·Num Rows·Rotation Rate)을 같은 이름 입력에 |
| Isaac Read Simulation Time | Simulation Time → Publish Laser Scan의 Time Stamp |
| ROS2 Publish Laser Scan | Topic Name = `scan_lidar`, Frame Id = `sim_lidar`(기본값) |

**카메라 → Image (Action Graph** `ROS2_Camera`**)**

| 노드 | 연결 / 설정 |
| --- | --- |
| On Playback Tick | Tick → Create Render Product의 Exec In |
| Isaac Create Render Product | Camera Prim = Robot_Camera. Exec Out → Camera Helper Exec In, Render Product Path → Render Product Path |
| ROS2 Camera Helper | Type = rgb, Frame Id = `sim_camera`, Topic Name = `rgb` |

```bash
# 터미널 2: 확인 (Isaac Sim에서 Play 중이어야 함)
source /opt/ros/jazzy/setup.bash
ros2 topic list | grep -E 'scan_lidar|rgb'
ros2 topic hz /scan_lidar        # 약 22~26 Hz
ros2 topic echo /scan_lidar --once
rviz2
```

- `/scan_lidar`: frame_id sim_lidar, 360°(−π ~ π)를 0.4° 간격, 0.4 ~ 100 m. `/rgb`: 640 × 480 rgb8.
- RViz2: Fixed Frame에 `sim_lidar` 직접 입력 → Add > By topic > /scan_lidar > LaserScan(Size 0.05 m 정도) → Add > By topic > /rgb > Image.
- Global Status가 빨간 것은 TF가 아직 없어서다. 오늘은 무시.

### 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| A를 누르면 오른쪽으로 돎 | 5.1 창이 관절을 [Right, Left] 순으로 만드는데 노드는 [왼쪽, 오른쪽] 순으로 속도를 냄 | 관절 칸을 서로 바꿔 넣기. 이미 만든 그래프는 ArrayNames의 input0·input1을 Rear_Left_Joint·Rear_Right_Joint 순으로 |
| 키보드가 안 먹음 | 키 입력이 뷰포트로 안 감 | Play 후 뷰포트를 한 번 클릭 |
| Xform에 Rigid Body를 줄 수 없다는 오류 | 공식 본문의 알려진 문제 | 자식 Prim을 잠시 밖으로 빼고 → Rigid Body 추가 → 다시 넣기 |
| "missing xformstack reset when child of another enabled rigid body" 빨간 오류 | Sensor_Mount에 Rigid Body를 줘서 강체 안에 강체가 생김 | Sensor_Mount 우클릭 > Remove > Physics > Rigid Body (Colliders만 남김) |
| 카메라 이름이 안 바뀜, nested gprims 경고 | Sensor_Mount가 Cube(gprim)라 아래 Prim 편집이 막힘 | Edit > Preferences > Stage > Authoring에서 Allow nested gprims authoring 체크 |
| 카메라 기즈모가 너무 큼 | 화면 표시 문제 | 뷰포트 설정 > Gizmos > Gizmo Camera Scale을 낮춤(예: 0.01) |
| 장애물이 로봇 안에 생김 | 로봇을 선택한 채 Create | Stage 빈 곳을 클릭해 선택을 푼 뒤 만듦 |
| 라이다 선이 장애물을 통과 | 장애물에 충돌 모양이 없음 | 장애물에 Colliders Preset |
| RViz에 점이 안 보임 | Fixed Frame ≠ frame_id | Fixed Frame = `sim_lidar` |
| `ros2 topic list`에 안 나옴 | Play가 아니거나 ROS_DOMAIN_ID가 다름 | Play 확인, 두 터미널의 `echo $ROS_DOMAIN_ID` 비교 |
| 점이 로봇 바로 옆에 동그렇게 찍힘 | 라이다가 바퀴를 봄 | Lidar를 조금 더 위로 |

### 내 메모 (RemNote)

[RemNote 11월 25일 데일리 문서](https://www.remnote.com/w/6ad729eabbafaa9b9157b9c2/November-25th-2026-3MkZoxkpnhloWffLY)에 적어 둔 메모를 옮기고, 틀린 부분은 고쳤다(아래 '고친 내용' 참고).

**PID**

- PID : Oscillation 존재 Vt = Vp + Vi + Vd
- P : Error * Gp = Vp
- I : Vi = Sigma(error × dt) * Gi, Vr = Vp + Vi (PI 제어 출력). 계속 남는 오차를 쌓아서 없앰
- 두 바퀴의 차이로 인한 각변화도 PI 제어 가능
- Error(theta) * Gp + sigma(Error(theta)) * Gi = theta dot
- D : 오차가 줄어드는 속도를 보고 미리 브레이크를 걸어 오버슈트·진동을 줄임 (그 결과 정착이 빨라짐)
- (Ec - Epre) / dt * Gd = Vd

**spring, damper**

- spring : F = −k * x ⇒ P제어의 역할 (변위에 비례해 되돌리는 힘)
- damper : F = −c * v ⇒ D제어 역할. 속도에 비례하는 저항으로 진동을 줄임 (Angular Drive의 Damping이 이 값)

**ROS 2 / Isaac Sim**

- 토픽 발행시 발행된 시간 time stamp도 포함
- Isaac Read Lidar Beams : 라이다 데이터 읽는 노드

**고친 내용**

| 원래 메모 | 고친 것 | 이유 |
| --- | --- | --- |
| (Ec - Epre) % dt | (Ec - Epre) / dt | %는 나머지 연산. 미분은 오차 변화량을 dt로 나눔 |
| D : 빠르게 목표값에 수렴하도록 | 오버슈트·진동을 줄임 | 빠르게 가는 건 P의 역할. D는 넘침을 막는 브레이크 (1일차 실습 ②: PD가 오버슈트 2.9%) |
| damper : 목표에 빠르게 도달하도록 | 진동을 줄임 | 댐퍼는 속도에 비례하는 저항 |
| Sigma(error) | Sigma(error × dt) | 적분은 오차에 시간 간격을 곱해 더함 |
| spring : F = k * x | F = −k * x | 스프링 힘은 변위 반대 방향 |
| Isaac Lidar Beams | Isaac Read Lidar Beams | 실제 노드 이름 |

#### 외부 자료로 보강한 정리

위 RemNote 메모를 공식 문서·제어 교재와 대조해 보충했다(2026-11-26).

**PID 한 번에 정리**

- 연속식: u = Kp·e + Ki·∫e dt + Kd·de/dt. 코드(이산)로는 `Vi += Ki·e·dt`, `Vd = Kd·(e − e_prev)/dt`. 메모의 Vt = Vp + Vi + Vd가 이 합이다. ([Åström, Advanced PID Control 3장](https://skoge.folk.ntnu.no/puublications_others/books/%C3%85strom-2006_Advanced%20PID%20Control/3.PID%20Control.pdf))
- 역할: P는 위치 오차를, D는 오차의 속도를, I는 쌓인 오차를 0으로 만들려고 한다. ([WPILib PID 입문](https://docs.wpilib.org/en/latest/docs/software/advanced-controls/introduction/introduction-to-pid.html))
- Kp를 키우면 빨리 올라가지만 오버슈트·진동이 늘고, 빠름과 안 넘침을 Kp 하나로 동시에 얻기 어렵다. 그 빈틈을 D가 메운다. ([LibreTexts PID 한계](https://eng.libretexts.org/Bookshelves/Industrial_and_Systems_Engineering/Chemical_Process_Dynamics_and_Controls_(Woolf)/09%3A_Proportional-Integral-Derivative_(PID)_Control/9.06%3A_PID_Downsides_and_Solutions))
- 적분 와인드업: 모터가 최대치에 걸려 있는 동안에도 I가 계속 쌓이면 나중에 크게 넘친다. 1일차 `pid.py`의 "출력이 한계일 땐 적분 안 함"이 이 대책(anti-windup). ([Åström 3장](https://skoge.folk.ntnu.no/puublications_others/books/%C3%85strom-2006_Advanced%20PID%20Control/3.PID%20Control.pdf))

**스프링 · 댐퍼 ↔ Isaac Sim 관절 드라이브**

- P 제어기는 오차에 비례해 당기는 소프트웨어 스프링(F = k·(목표 − 현재))처럼 동작한다. ([WPILib](https://docs.wpilib.org/en/latest/docs/software/advanced-controls/introduction/introduction-to-pid.html))
- Isaac Sim 관절 드라이브는 이득이 두 개인 비례 제어기다: 힘 = Stiffness × (목표 위치 − 현재 위치) + Damping × (목표 속도 − 현재 속도). 이름이 Stiffness(스프링)·Damping(댐퍼)인 건 역사적 이유이고, 목표 속도가 0이면 그냥 PD 제어기가 된다. ([Isaac Sim Gain Tuner](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/robot_setup/ext_isaacsim_robot_setup_gain_tuner.html), [Joint Drive 튜닝](https://docs.isaacsim.omniverse.nvidia.com/4.2.0/advanced_tutorials/tutorial_advanced_joint_tuning.html))
- **보충할 점**: 2일차 바퀴처럼 Stiffness 0 + Target Velocity로 쓰는 "속도 드라이브"에서는 Damping이 진동을 줄이는 브레이크라기보다 **속도 오차에 곱하는 P 이득**이 된다. Damping 10000이 "목표 속도를 강하게 따라가게" 만든 이유. 바퀴처럼 계속 도는 관절은 속도 목표를 쓰는 게 공식 권장이다. ([Gain Tuner: Drive Modes](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/robot_setup/ext_isaacsim_robot_setup_gain_tuner.html))
- 위치 드라이브를 손으로 맞출 땐 Damping을 Stiffness보다 한 자릿수 작게 시작하면 대체로 넘치지 않는다는 공식 팁. ([Joint Tuning 4.5](https://docs.isaacsim.omniverse.nvidia.com/4.5.0/robot_setup/joint_tuning.html))

**time stamp (ROS 2 Header)**

- 센서 메시지의 `header`는 `stamp`(초 + 나노초)와 `frame_id` 두 칸이다. 시각이 찍힌 데이터를 특정 좌표계에 묶어 보내려는 표준 머리말. ([std_msgs/Header (Jazzy)](https://docs.ros.org/en/jazzy/p/std_msgs/msg/Header.html), [ROBOTIS e-Manual](https://emanual.robotis.com/docs/en/popup/op3_ros2/std_msgs_Header))
- 라이다라면 stamp는 스캔을 찍은 시각을 뜻한다. 그래서 Isaac Read Simulation Time(시뮬레이션 시계)을 넣는다. RViz의 Fixed Frame 문제는 frame_id 칸 이야기. ([ROS Messages 설명](https://whiteoak.umd.edu/roswiki/Messages.html))

**Isaac Read Lidar Beams**

- `isaacsim.sensors.physx` 확장의 노드. 라이다 한 바퀴 스캔 데이터를 버퍼로 들고 있다가, 스캔이 끝날 때 Exec Out을 낸다. 출력으로 Azimuth/Depth Range, Horizontal Fov·Resolution, Intensities, Linear Depth, Num Cols/Rows, Rotation Rate 등을 준다(오늘 Publish Laser Scan에 이은 그 칸들). ([5.1 노드 문서](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/py/source/extensions/isaacsim.sensors.physx/docs/ogn/OgnIsaacReadLidarBeams.html))
- PhysX 라이다는 PhysX 레이캐스트로 거리를 재서 항상 정답값(노이즈 없음)을 주고, 비시각 재질과는 상호작용하지 않는다. 충돌 모양만 보는 이유와 같은 맥락. ([PhysX SDK lidar](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/sensors/isaacsim_sensors_physx_lidar.html))
- 버전 주의: Isaac Sim 6.0부터 PhysX 라이다는 지원 중단(deprecated)되고 `RaycastSensor`로 바뀐다. 강의는 5.1이라 그대로 쓰면 되지만, 나중에 6.x로 옮기면 이 그래프를 바꿔야 한다. ([PhysX SDK lidar](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/sensors/isaacsim_sensors_physx_lidar.html))

### 복습 질문

> [!question]- Q1. Differential Controller를 만들기 전에 Articulation Root를 먼저 붙이는 이유는?
> Articulation Root가 관절로 이어진 강체들을 하나의 로봇으로 묶어야 물리 엔진이 한꺼번에 풀고(덜 흔들림), 제어기가 관절을 이름으로 찾을 수 있다.

> [!question]- Q2. Isaac Sim 5.1에서 Differential Controller 창의 관절 칸을 이름대로 넣으면 어떻게 되고, 왜인가?
> 창은 관절 목록을 [Right 칸, Left 칸] 순으로 만드는데 노드는 [왼쪽, 오른쪽] 순으로 속도를 내서 좌우가 뒤바뀐다. A를 누르면 오른쪽으로 돈다(+1 rad/s, 3초에 −10.7°). 서로 바꿔 넣으면 +13.2°로 맞다.

> [!question]- Q3. 라이다 선이 장애물을 그냥 통과하는 이유는?
> PhysX 라이다는 물리 충돌 모양만 본다. 장애물이 보이는 모양만 있으면 통과하므로 Colliders를 줘야 한다.

> [!question]- Q4. 5.1에서 Sensor_Mount에 Rigid Body를 주지 않는 이유는?
> 이미 강체인 Front_Sensor 아래에 또 강체를 두면 "missing xformstack reset" 오류가 난다. 충돌 모양만 필요하므로 Colliders Preset만 준다.

> [!question]- Q5. RViz2에 라이다 점이 안 보일 때 가장 먼저 확인할 것은?
> Global Options의 Fixed Frame이 Isaac Sim에서 설정한 Frame Id(`sim_lidar`)와 같은지. 그다음 Isaac Sim이 Play 중인지, 두 터미널의 ROS_DOMAIN_ID가 같은지.

> [!question]- Q6. ROS2 Publish Laser Scan의 Time Stamp에는 무엇을 연결하나?
> Isaac Read Simulation Time의 Simulation Time. 토픽에 발행 시각이 함께 들어간다.

> [!question]- Q7. RViz에서 로봇은 가만히 있고 주변이 움직이는 것처럼 보이는 이유는?
> Fixed Frame이 로봇에 붙은 `sim_lidar`이기 때문이다. 지도 기준으로 보려면 TF가 필요하다(5일차).
