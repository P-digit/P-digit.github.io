> 5일차 · DLI 1 통합 실습 · Best Practices for Robotics and OpenUSD

새 공식 과정 없이 DLI 1에서 배운 것(화면·물리·관절·URDF 가져오기)을 로봇팔 + 그리퍼 + 학습 장면으로 묶은 날이다. 로봇 에셋을 기능별 층(base·physics·robot·sensor)으로 나누는 구조를 보고, 그리퍼 손가락 메시를 Mesh Merge Tool로 합쳤다. ROS 2 robot_state_publisher에서 UR10e를 가져와 Robot Assembler로 그리퍼를 붙이고 Variant로 만든 뒤, 창고 장면에 배치해 Physics Inspector와 IK 예제로 움직였다.

### 학습 목표

새 공식 과정은 없는 DLI 1 통합 실습. 공식 자료: Best Practices for Robotics and OpenUSD (강의 자산 LOUSD_RBP_[assets.zip](http://assets.zip/), 예제 LOUSD_RBP_[example.zip](http://example.zip/)).

- 로봇 에셋의 층 구조를 이해하고 메시·충돌체를 최적화한다
- ROS 2 로봇 설명(robot_description)에서 로봇팔을 가져온다
- 그리퍼를 붙여 Variant로 만든다
- 창고 학습 장면을 조립하고 IK로 움직인다

이어지는 내용: [4일차 · URDF로 Carter 가져오기·센서 달기·Nova Carter](https://app.notion.com/p/42447b7cc0d481a59ae4d03e217a3686)

### 핵심 개념

#### 관절 종류

| 관절 | 뜻 | 예 |
| --- | --- | --- |
| continuous | 한계 없이 끝없이 도는 회전 | Carter 바퀴 (4일차) |
| revolute | 각도 한계가 있는 회전 | UR10e 팔 관절 6개 |
| mimic | 다른 관절을 따라 움직임 | 그리퍼 손가락 (finger_joint 하나로 4개가 함께 닫힘) |

- URDF에 있는 것(링크·관절·질량·관성·모양·센서 위치)은 USD에서 Prim·Geometry·Rigid Body·Collider·Articulation·Joint·Material·층(Layer)·참조(Reference)·덮어쓰기(Override)로 표현된다.

#### 에셋의 기능별 분리 (층 구조)

- 한 로봇을 base(메시)·physics(충돌체·물리)·robot·sensor 층 파일로 나누고, 맨 위 인터페이스 층(예: `robotiq_2f_140.usd`) 하나만 열면 렌더링·물리·학습이 모두 같은 파일에서 시작한다.
- 4일차 URDF Importer가 만든 `carter/configuration/`의 base·physics·robot·sensor 파일이 바로 이 구조다.
- 메시는 base 층에서, 충돌체는 physics 층에서 고친다.
- Variant: 한 USD에 여러 구성을 넣어 두고 고르는 기능. 그리퍼 에셋은 Physics(None/PhysX)·Robot(None/Robot)·Sensor(None/Sensors) Variant를 가진다.

#### 메시 최적화 (Mesh Merge Tool)

- CAD에서 가져온 로봇은 강체 하나에 메시가 수십 개인 경우가 많아 렌더링·충돌 계산이 늘어난다. 한 강체의 메시를 하나로 합치고, 같은 모양은 인스턴스(instanceable)로 재사용한다.
- 합친 메시는 새 Prim이라 충돌체가 없다 → physics 층에서 Colliders Preset + Approximation = Convex Hull을 주어야 한다.
- 결과: base 층 메시 28 → 23, 그리퍼 전체 메시 22 → 18 (NVIDIA 완성본과 같음).

#### ROS 2 robot_description에서 가져오기

- 로봇 회사는 URDF를 ROS 패키지(xacro)로 배포한다. ROS 2로 띄우면 robot_state_publisher가 완성된 URDF를 `/robot_description`으로 들고 있고, Isaac Sim이 그것을 받아 가져온다.
- 로봇팔은 Static Base + Position, 관절 6개 Natural Frequency = 300. 같은 Natural Frequency를 줘도 Stiffness는 관절이 움직이는 질량·관성에 맞춰 관절마다 다르게 계산된다(shoulder_pan 17,249 · elbow 556,712 · wrist_3 690).

#### Reference vs Payload, IK

- 장면에 에셋을 복사해 넣지 않고 참조한다. 로봇처럼 큰 에셋은 Payload(필요할 때만 불러오기)로 넣는다.
- IK(역기구학): 손끝(끝 작용점)이 가야 할 위치·방향을 주면 관절 각도를 계산한다. **IK는 장애물을 모르고** 관절 각도만 계산하므로, 받침대·공구함에 막히면 물리 때문에 거기서 멈춘다.
- Physics Inspector: 관절마다 Drive Target·Joint State 슬라이더로 로봇을 직접 움직여 물리 설정을 확인한다. 물리가 맞으면 이 장면을 그대로 Isaac Lab 학습·시험 환경으로 쓴다.

### 환경 메모

| 단계 | 공식 본문 | 이 과정 (5.1 · Jazzy) |
| --- | --- | --- |
| 메시 합치기 선택 대상 | /meshes/... 또는 right_inner_finger/right_inner_finger | right_inner_finger/visuals/robotiq_arg2f_140_inner_finger (/meshes 아래는 숨겨진 원본이라 Submeshes 0) |
| 충돌체 적용 | left · right 두 경로 | left 하나 (right가 같은 원본을 씀) |
| Colliders Preset의 Approximation | Convex Hull | 5.1은 비워 둠(none) → 목록에서 Convex Hull 선택 |
| ROS 2 노드에서 가져오기 | Humble을 Python 3.11로 다시 빌드 | Isaac Sim 내장 Jazzy (시스템 ROS source 안 함) |
| Robot Assembler 그리퍼 | 직접 최적화한 파일 | 체크포인트 robotiq_2f_140_final (IsaacRobotAPI 스키마 필요) |
| robot 위치 | (0.02, 0.285, 1.175) — 받침대 기준 상대값 | (−3.98, −4.715, 1.175) |

- **왜 이 실습만 시스템 ROS를 source하지 않나:** ROS 2 노드에서 가져오기는 Isaac Sim 안에서 Python rclpy로 서비스를 부른다. Isaac Sim 5.1은 Python 3.11, Ubuntu 24.04의 시스템 Jazzy는 Python 3.12라 시스템 rclpy를 쓸 수 없다. 다른 날처럼 source해도 ROS 2 브리지(토픽)는 동작하지만 이 메뉴는 동작하지 않는다.

### 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| Mesh Merge의 Submeshes가 0, 빈 메시 생성 | /meshes 아래 숨겨진 원본을 골랐음 | visuals 아래 회색 글씨(인스턴스) 항목 선택 |
| 합친 손가락이 떠 보임 | 합친 메시가 원래 위치값을 가짐 | Translate·Orient 파란 네모 → 기본값 0 |
| 오른쪽 손가락 충돌체가 패드 상자만 남음 | 합친 메시(새 Prim)에 충돌체 없음 | physics 층에서 Colliders Preset + Convex Hull |
| `primvar 'st' ... buffer size` 노란 경고 | 합친 메시의 텍스처 좌표 경고 | 완성본도 같음, 시뮬레이션 영향 없음 |
| ROS2 URDF Node 관절 표가 안 나옴 | view_ur가 꺼져 있거나 시스템 ROS를 source한 터미널에서 Isaac Sim 실행 | 터미널 2 확인, Refresh, 터미널 1은 내장 Jazzy 환경변수로 |
| USD Output 칸에 입력이 안 됨 | 직접 입력 불가 | 폴더 아이콘으로 선택 |
| Robot Assembler의 Attach Robot 목록이 비어 있음 | 그리퍼 파일에 IsaacRobotAPI 스키마 없음 | robotiq_2f_140_final 체크포인트 사용 |
| Variant가 한 번에 안 바뀜 | — | 한 번 더 고름 |
| IK 손끝이 목표 앞에서 멈춤 | IK는 장애물을 모름, 물체에 막힘 | 장애물 옆으로 돌아가는 목표를 줌 |

**관절**

- D6 : 6 자유도 joint (PhysX D6 Joint. 이동 3축 + 회전 3축을 축마다 잠그거나 범위를 줄 수 있는 범용 관절)
- Mimic joint : 그리퍼의 손가락처럼 두 손가락이 동시에 움직이게 하는 joint(속성). 다른 관절의 움직임을 정해진 비율로 따라감 (finger_joint 하나로 손가락 4개)

**UR10e**

- `ros2 launch ur_description view_ur.launch.py ur_type:=ur10e`
- ur_type : 불러올 UR 로봇 모델 이름 (ur3e · ur5e · ur10e 등). 모델 번호가 대략적인 가반하중(들 수 있는 무게, kg) 등급을 뜻함
- ee : end effector (끝단에 달려서 작업하는 부위. 오늘은 그리퍼, Variant 이름도 ee_link)
- 플랜지 : 로봇팔 손목 끝의 원판. 엔드 이펙터(그리퍼·공구)를 장착하는 부위 (오늘 wrist_3_link에 그리퍼를 붙임)

**고친 내용**

| 원래 메모 | 고친 것 | 이유 |
| --- | --- | --- |
| ur_type : payload (들 수 있는 무게?) | 로봇 모델 이름 | ur_type은 어느 모델을 불러올지 정하는 인자. 가반하중은 모델 번호가 대략 나타내는 것 |
| 플렌지 부 : 로봇을 연결해주는 부위 | 플랜지 : 엔드 이펙터를 장착하는 손목 끝 원판 | 로봇끼리가 아니라 팔과 공구를 잇는 부위. 맞춤법도 플랜지 |
| D6, Mimic, ee | 설명 보충 | 틀린 건 아니지만 뜻을 분명히 |

### 복습 질문

> [!question]- Q1. 로봇 에셋을 base·physics·robot·sensor 층으로 나누는 이유는?
> 기능별로 따로 고칠 수 있고(메시는 base, 충돌체는 physics), 맨 위 인터페이스 층 하나만 열면 렌더링·물리·학습이 모두 같은 파일에서 시작한다.

> [!question]- Q2. 메시를 합친 뒤 physics 층에서 충돌체를 다시 주는 이유는?
> 합친 메시는 새 Prim이라 충돌체가 없다. 빼면 오른쪽 손가락 충돌체가 패드 상자 하나만 남는다. Colliders Preset + Approximation Convex Hull을 준다.

> [!question]- Q3. finger_joint 하나만 바꿨는데 손가락 4개가 함께 닫히는 이유는?
> 나머지 손가락이 finger_joint를 따라 움직이는 Mimic 관절이기 때문이다.

> [!question]- Q4. UR10e를 ROS 2 노드에서 가져올 때 Isaac Sim 터미널에서 /opt/ros/jazzy를 source하지 않는 이유는?
> 이 메뉴는 Isaac Sim 안에서 Python rclpy를 쓰는데, Isaac Sim 5.1은 Python 3.11이고 시스템 Jazzy는 Python 3.12라 맞지 않는다. 대신 내장 Jazzy 라이브러리를 환경변수로 지정한다.

> [!question]- Q5. Natural Frequency를 모두 300으로 줬는데 관절마다 Stiffness가 다른 이유는?
> Stiffness는 그 관절이 움직이는 질량·관성에 맞춰 계산된다. 무거운 부분을 움직이는 elbow(556,712)는 크고, 끝의 wrist_3(690)은 작다.

> [!question]- Q6. 장면에 로봇은 Payload로, 나머지는 Reference로 넣는 이유는?
> 로봇처럼 큰 에셋은 필요할 때만 불러올 수 있게 Payload로 넣는다. 둘 다 장면 파일에 복사하지 않고 원본을 참조한다.

> [!question]- Q7. IK 목표를 공구함 바로 위에 두었더니 손끝이 34 cm 떨어진 곳에서 멈춘 이유는?
> IK는 장애물을 모르고 관절 각도만 계산한다. 로봇이 받침대·공구함에 물리적으로 막혀 거기서 멈춘 것이다.
